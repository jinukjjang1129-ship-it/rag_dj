# 취업규칙·기업정보·크롤링 검증

## 원본 조사와 보존

ZIP 6개, 원본 Git mirror, 추출 코드/노트북/자료를 별도 보존했다. 이 변경은 SCH 검증 브랜치 위의 후속 Draft 변경이며 main을 수정하지 않는다. 기존 `rag_dj`, `ocv__`, `ml_streamlit`을 확인했고 `attachment-profile-chatbot`도 RAG 기술을 쓰지만 개인 연애 성향 상담이라는 별도 문제여서 기업·대학·취업규칙과 합치지 않았다. `survey` README만으로 현재 대상과의 중복을 확인할 수 없었다.

회사 API/local ZIP은 모델 모드, API 의존성 제거, 카테고리 보존, 분산 검색, Selenium 대안에서 다르다. 특히 로컬 버전에 이미 사업분야별 검색과 질의 임베딩 1회 재사용이 있었다. 이를 이번에 새로 구현한 성과로 표시하지 않는다. 사용자 본인이 강의를 진행했으므로 ‘실습’ 문구를 외부 예제 수강의 증거로 해석하지 않는다. 별도 document-rag-experiments 저장소를 늘리지 않고 같은 저장소에 관련 예제를 통합했다.

## 발견한 실행·분할 문제

원본 취업규칙 rag.py는 파일 전체의 들여쓰기로 IndentationError가 발생한다. 비교용 사본에서는 textwrap.dedent만 적용했다. 원본 조항 regex는 본문의 ‘제N조에 따라’까지 새 경계로 나누며 페이지를 보존하지 않는다. 큰 조항이 부분으로 나뉜 뒤 top-k에서 뒷부분만 반환될 수도 있다. 이를 줄 시작의 조항 헤더로 분리하고 PDF 페이지 span을 추적하는 공통 모듈로 교체했다.

번호 질의는 여러 조항과 각 부분을 모두 반환한다. 의미 검색으로 찾은 조항도 전체 부분을 확장한다. 정확 일치·확장 부분에는 가짜 유사도 100%를 붙이지 않는다. 약한 검색 결과가 모두 제외되어도 원래처럼 1개를 강제로 되살리지 않는다. cosine 모델/metric 기록이 없는 기존 인덱스를 조용히 재사용하지 않고 새 경로를 요구한다. 원문이 바뀐 경우에도 이전 버전과 혼합하지 않는다.

회사 정제는 ‘주요제품’ 앞을 무조건 잘라 정상 본문을 잃거나 ‘제품문의’ 이후의 필요한 정보를 모두 버리는 동작을 피하고, 확인 가능한 footer만 제거한다. 원문이 늘어난 부분은 잡음이 남을 수 있어 더 많은 수작업 품질 검수가 필요하다. 원문을 추가 공개하지 않는다.

## 실제 실행

- 취업규칙 PDF38쪽 → 96개 청크, 93개 article label(기타 포함). 모든 청크에 실제 페이지 span이 있다. 원본 분할의 비교 청크 수는133개다.
- 제공 회사 JSON19페이지 →33개 청크. 로컬 버전의 기존 정제 비교는27개다. 정제 길이가 늘었다는 사실을 품질 개선으로 간주하지 않는다.
- 같은 자료 2회 적재 결과는 각각96/33개로 동일하다. 안정 ID와 기존 ID 확인으로 동일 문서를 다시 임베딩하지 않는다.
- 실제 한국어 임베딩·Chroma를 사용했고, 브라우저에서 회사 4개 사업분야 목록과 실제 PDF 업로드·검색을 확인했다. 공개 화면에는 사내 문서 답변 본문을 넣지 않았다.
- Playwright 로컬 허용 fixture는 정상 추출1건, 503 재시도 후 추출1건, 404 기록1건을 확인했다. 이 결과를 실사이트 성공률로 표시하지 않는다.

## 동일 평가셋의 의미

`evaluation/evaluate_documents.py`는 같은 PDF/회사 JSON으로 기존 코드와 수정 코드를 실행한다. 원본 PDF와 JSON은 별도로 있어야 한다. 기존 코드 실행에는 로컬 사본 경로가 필요하며 원본 .env는 복사하지 않는다. 외부 API를 호출하지 않는다.

취업규칙 10문항은 번호가 명시된5문항과 근로시간/연차유급휴가/휴일/퇴직/징계5문항이다. 원본의 조항 헤더를 미리 gold anchor로 정하고 반환 텍스트에 포함됐는지 확인한다. 번호만 같은 본문 참조를 정답으로 세지 않도록 한 보수적 검사다. 다만 다른 관련 조항도 유효한 근거일 수 있어 헤더 미포함을 답변 오답으로 단정하지 않는다.

회사10문항은 반도체/디스플레이/신재생/발포제/회사개요/채용/ESG/윤리경영/혁신경영/위치의 원래 URL 반환을 확인한다. 사업분야4개 포함은 별도 목록 검사다. 원문 답변의 사실 정확도를 평가한 것이 아니다.

초기 들여쓰기만 복구한 취업규칙 baseline은 gold 헤더1/10, 새 코드는8/10이다. 페이지 기록은0/10→10/10이다. 회사 source hit와4개 분야 포함은 기존 로컬 버전과 새 코드 모두100%다. 이미 있던 성과를 새 개선으로 포장하지 않는다. 취업규칙의 워밍업 후 검색 중앙값은 JSON의 실제 측정값을 따른다. 모델 로드·문서 적재·사용자 탐색·생성 시간을 제외하므로 원래 ‘10분→3분’과 비교할 수 없다.

## 실패 사례와 미검증 항목

휴일·징계 의미 질문은 gold anchor를 반환하지 못했다. 유사한 다른 조항이 함께 존재하므로 사람의 질문별 근거 검수와 다중 정답 라벨이 필요하다. 명확히 무관한3문항에서 근거를 반환한 수는 취업규칙 기존3→현재1, 회사 기존3→현재0이다. 회사의 범위 검사는 제한된 규칙이며 이것으로 환각률0%를 주장하지 않는다. 임곗값0.8은 보정된 확률이 아니고 더 넓은 별도 질문셋으로 검증해야 한다.

초기 검색 평가는 생성 없이 실행했으며, 후속 검증에서 별도 Ollama CPU 컨테이너와 공식 gemma3:4b를 실제 실행했다. 동일 문항의 생성 답변·중단·정형 조회를 [별도 보고서](generation-validation.md)에 기록한다. API 모드는 실제 호출 검증하지 않았다. 긴 근거는 잘라서 완전한 답변이라고 하지 않고 추출식 근거를 유지한다.

## 실사이트 접근과 저장

현재 robots.txt 응답은 HTTP403이었다. 원본 주석의 ‘허가받음’ 문구만으로 현재 허가를 확인했다고 주장하지 않았다. 허용 상태를 읽을 수 없는19개 대상은 모두 robots_unverified로 기록했고 본문 수집은 수행하지 않았다. 사이트가 robots로 명시적으로 전부 금지한다고 단정한 것도 아니다. 접근 제한을 우회하거나 로그인·차단 해제를 시도하지 않았다.

출력은 성공/HTTP오류/전송오류/robots 미확인 상태를 분리한다. 일시적 서버/전송 실패의 bounded retry, 원문 hash·수집시각·HTTP상태·실제 URL·selector·body fallback 검토 표시, 임시파일 후 원자적 저장을 적용했다. 운영 재수집에는 허용된 접근 환경과 정책 확인이 필요하다. 복잡한 Retry-After·다중 도메인 rate limit, 사이트 DOM 변경 전체, 사용자 입력 URL의 공개 서비스 수준 검증은 후속 과제다.

## 공개 제외와 기여

PDF, 신규 수집 JSON, 벡터 저장소, 대화 이력, 회원/학습 parquet, 원본 .env의 비어 있지 않은 키/비밀번호는 게시하지 않았다. 원래 main의 pages.json은 변경하지 않았으며 재배포 권한은 여전히 확인해야 한다. 원본 ZIP 및 Git 이력은 로컬에 보존했다.

본인 역할은 사용자 확인/이력서 기준 RAG·크롤링 설계와 구현, 기술 교육 자료 준비 및 강의다. 강의 코드와 제품 프로토타입, 이번 검증 변경을 구분한다. 5문항 정보 탐색10분→3분과 교육8회는 기존 기록이며 이번 검색 벤치마크로 재입증하지 않았다.

면접에서는 페이지 근거를 어떻게 보존했는지, inline 조항 참조와 헤더를 어떻게 구분했는지, 로컬 버전에 이미 있는 개선을 어떻게 발견했는지, idempotent 적재가 왜 필요한지, 수집 보류·검색 성공·생성 답변 정확도를 어떻게 나누었는지를 설명한다.

현재 생성 context 상한은 문자 수 기준이며 토큰 수와 같지 않다. 실제 생성 모델 토크나이저의 예산과 인용된 사실의 정확도 검증은 남아 있다.

최종 8문항 실제 생성 회귀 검토에서는 전형료 라우팅과 정형 목록 개선을 확인했다. 근로시간의 모델 인용 오류는 원문 fallback으로 처리했으며, 일정 답변 중단과 회사 답변의 과도한 인용은 남아 있다. [문항별 결과](generation-validation.md)를 참고하며 검색 hit를 생성 정확도로 바꾸어 보고하지 않는다.
