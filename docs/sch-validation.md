# SCH 검증 기록

## 범위와 원본

ZIP v2/v3를 별도 원본 디렉터리에 보존했다. 기존 `rag_dj` 저장소의 main을 수정하지 않고 `apps/sch`를 추가한 Draft 변경으로 제시한다. 저장소 중복을 줄이기 위해 새 공개 저장소를 즉시 만들지 않았다. 향후 `multi-domain-rag-system` 이름으로 바꾸거나 분리하는 것은 별도 검토 대상이다.

v2/v3의 기존 Python 14개 중 9개는 동일하며, engine/department/admission과 admission/paper ingest 5개가 다르다. v3는 그래프 적재, FastAPI·HTML 데모 및 실험 노트북을 추가했다. v3 README는 v2라는 이름을 유지하고 있어 실제 코드와 문서를 대조했다. v2에는 제공된 저장 인덱스가 없고 v3에는 학과 147/입시 70/논문 334개 청크가 있다.

## 수정의 근거

- v3가 교수 검색 k를 10으로 늘려도 fallback 요약은 상위 3개만 사용한다. 목록 질문은 메타데이터로 모든 유효 교수 항목을 가져와 결정적으로 렌더링한다. 일반 교수 연구분야 질문은 벡터 경로를 유지한다.
- AI빅데이터학과의 ‘오시는길’이 professor로 표기된 실제 오분류를 발견했다. 교수 이름 형식의 제목을 확인하고 적재 시 잘못된 유형을 general로 분류한다. 적재 자료의 목록이 현실 세계 전체 목록이라는 가정은 하지 않는다.
- 명시적인 where 필터가 비어도 전체 컬렉션으로 조용히 이동하던 동작을 기본 차단한다. fallback은 명시적으로 허용한 호출만 수행한다.
- 검색은 원문 공백 정규화 hash로 중복 제거 후 k개를 선택한다. 원본 평가셋에서 중복 0개였으므로 중복 제거 효과에 대한 성과를 주장하지 않는다.
- cosine 거리에서 만든 표시값을 답변 신뢰도와 구분한다. 기존 관련도 임곗값 32는 보정되지 않은 heuristic이므로 유지하되 성능 근거로 사용하지 않는다.
- Ollama 장애 시 추출식 결과임을 generation_mode로 남기고 로그에는 예외 유형만 기록한다.
- 입시 PDF 44쪽의 첫 두 줄에 있는 서류평가 참조가 섹션 헤더로 오인되어 이전 전형이 끊긴다. 번호가 붙은 전형 속성의 연속 페이지에서는 이 참조를 섹션 경계로 해석하지 않는다.
- ‘공통 지원자격’과 ‘전형별 모집인원 및 지원자격’ 복합 표를 별도 필드로 보존한다. 복합 표에서 모집인원을 임의 합산하지 않는다.
- 그래프 목록·속성은 조회된 값을 직접 렌더링하고 파일명·PDF 실제 페이지를 응답 근거로 유지한다. 그래프 결과를 LLM이 다시 줄여 누락시키지 않도록 했다. 동기 Neo4j 작업은 FastAPI 동기 엔드포인트로 실행하여 이벤트 루프를 막지 않도록 했다.

## 동일 평가셋과 지표 정의

`evaluation/evaluate_sch.py`의 23문항: 교수 목록 5, 교육과정 5, 입시 5, 논문 5, 무관 질문 3. AI빅데이터학과의 교수 항목은 유효한 원문 교수 레코드가 없으므로 정답 없음으로 평가한다. 자료가 있는 양성 질문은 19개다. 교수 목록 항목의 gold는 원문 제목과 유형을 함께 확인한 4문항이다. 기타 질문의 gold는 학과/섹션/파일 메타데이터에서 정한다. 이는 문장별 수작업 relevance 라벨이나 독립 전문가 평가를 대체하지 않는다.

세 버전 모두 **동일 v3 인덱스의 사본**과 실제 `jhgan/ko-sroberta-multitask` CPU 임베딩으로 실행했다. 원본 DB는 읽기 대상에서 복사해 변경하지 않았다. 따라서 비교는 검색·응답 코드에 대한 회귀 검사이며 v2 원래 적재 전체와 v3 전체 시스템의 비교가 아니다. PDF 파서 개선은 별도 같은 PDF의 필드 추출 평가로 비교했다.

- retrieval hit: gold 근거가 하나 이상 결과에 포함되었는가.
- evidence recall: 메타데이터로 정의한 gold 청크 중 찾은 비율.
- list answer coverage: 정답 목록 항목이 실제 출력 문자열에 포함된 비율. 자료 내부의 목록 포함률이며 자유 생성 답변의 정확도가 아니다.
- answer accuracy: 실제 LLM 답변을 정답과 비교하는 지표. 이번 실행은 null이다.
- latency: 워밍업 후 각 질문 3회 요청의 중앙값. 모델 로드·인덱스 최초 개방·Ollama 생성 시간은 제외한다. JSON에 측정값을 보존하며 성능 개선이라고 일괄 표현하지 않는다.

## 실패와 남은 검증

‘웹 취약점 관련 논문’ 질문은 초기 세 코드 모두 gold를 반환하지 못했다. 진단 결과 키워드 매칭 0개로 사전 차단되지만, 벡터 검색 자체는 해당 파일을 포함하고 최고 표시 점수 77.7로 임곗값 32를 넘었다. 추출 제목이 부정확해 원본 파일명을 보조 주제 단서로 추가했다. 같은 평가셋에서 수정한 회귀 결과이므로 독립적인 일반화 정확도가 아니다. 임곗값은 낮추지 않았다. 연구용 텍스트를 넣을 때 임베딩 모델의 최대 입력 길이 및 LLM에 전달하는 청크 잘림도 별도 검증해야 한다.

교수/입시 목록의 구성 자체가 옳은지는 외부 원문 대조가 필요하다. PDF의 필드가 비어 있지 않다는 것이 필드 내용의 정확도를 의미하지 않는다. 19→20개 필드 완전성 개선을 사실 정확도 향상률로 바꾸어 표현하지 않는다.

Ollama 로컬 포트 11434 연결은 실패했다. gemma3:4b 실제 생성·답변 정확도·end-to-end 지연은 미측정이다. 원본 환경변수의 지정 Neo4j 서버에 쓰기 없는 연결 검사를 시도했으나 ServiceUnavailable로 실패했다. 데이터 조회나 쓰기는 실행되지 않았다. URI·비밀번호는 출력·게시하지 않았다. 실 Neo4j 통합과 동시성·권한·인덱스 버전 호환 검증은 남아 있다.

이력서의 5문항 기준 정보 탐색 10분→3분과 사내 교육 8회는 사용자 설명/이력서에 따른 활동이다. 원래 질문·측정 조건·교육 일정 기록이 없어 이번 코드 실행으로 재입증하지 않았다.

## 포트폴리오와 면접

핵심 문제는 ‘문서를 찾았다’와 ‘빠짐없이 맞게 답했다’의 차이다. 본인 역할은 사용자 확인에 따라 시스템 설계·구현과 내부 교육 자료 준비/강의로 기록한다. 코드의 파일별 저작·팀 기여 범위는 증빙 없는 추정으로 확대하지 않는다. 이번 자동 검증·리팩터링 변경은 원본 개발과 구분한다.

설명할 질문: 목록 조회에 top-k를 쓰면 왜 빠지는가, Neo4j와 벡터 검색의 경계는 무엇인가, 임베딩 cosine 점수는 왜 정확도가 아닌가, 검색 실패와 생성 실패는 어떻게 분리하는가, 실제 자료를 공개하지 않고 어떻게 재현 방법을 제공하는가.

## OCR 환경 검증

초기 시스템에는 eng/osd 언어팩만 있었다. kor+eng 요청에서 한국어 팩 부재가 조용히 부분 처리될 수 있어, OCR 시작 전에 요구 언어팩을 모두 검사하도록 수정했다. 공식 tessdata_fast 한국어 팩을 로컬 작업 디렉터리에 받아 원문을 외부 API로 보내지 않고 재검증한다. OCR 실패 시 extraction_method=text_ocr_failed를 남긴다. 논문은 표 구조 재현이 필수인 입시 문서와 구분해 일반 텍스트 추출을 우선하고, OCR 이미지는 한 페이지씩 열고 닫는다. 원래 DB와 재생성 DB의 청크 수가 같아야 한다고 가정하지 않는다.

새 인덱스에는 embedding_model을 기록하고, 기록된 모델이 설정과 다르면 사용을 거부한다. 과거 인덱스의 모델 정보가 없으면 검증되지 않은 provenance로 남기며 같은 차원이라는 이유로 호환된다고 확정하지 않는다.

## 원본 자료 재적재

별도 로컬 인덱스로 학과 147, 입시 71, 논문 171개 청크를 생성했다. 논문 2개에 실제 kor+eng OCR을 적용했다. 원래 저장된 논문 334개와 다르며, 일반 텍스트 추출 방식·언어팩·pypdf 버전에 따라 청크가 달라지므로 동일 인덱스 재현을 주장하지 않는다. 원본 데이터와 두 인덱스는 각각 보존했다. 재생성 인덱스 검사는 rebuilt.json에 별도로 기록하며 공유 인덱스 코드 비교와 섞지 않는다.
